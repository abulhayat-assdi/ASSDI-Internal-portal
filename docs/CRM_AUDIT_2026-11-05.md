# CRM audit — 5 November 2026

## Defects reproduced and fixed

- Admin-created practice cases assigned to a student returned to the original administrator after L2 correction requests. Returns now use the last Agent owner from immutable escalation history. Eligibility is checked; unavailable Agents do not receive new work. Creator identity and existing SLA deadlines stay intact.
- Reassigning a complaint left outstanding callbacks with the previous owner. Individual and bulk reassignment now transfer open callbacks belonging to that owner, inside the same transaction. Completed callbacks retain their attribution. Assignment history/audit records the transfer count.
- Complaint list polling could apply text the user had typed without submitting Search. Older delayed responses could replace newer search results. Polling now uses only submitted criteria and list requests reject stale responses.
- Complaint list pagination accepted inconsistent invalid values. It now validates integer pages 1–10000, matching the training directory.
- Browser Forward from a directly opened Settings page could restore the Settings tab at the Dashboard URL. URL-derived navigation now restores Dashboard correctly; escalation handoffs also update the URL when returning to the escalation list.

## Validation

39 unit/integration tests pass against isolated PostgreSQL databases, including regression cases that failed before the fixes. Coverage includes restricted runtime RLS, course/workspace boundaries, membership revocation, atomic writes/idempotency, field validation, both phone fetch modes, workflow/closure locks, SLA snapshots, reports, 500-customer/250-case dataset preservation, notifications, assignment concurrency, personal progress, actual handling-Agent returns, inactive-Agent fallback and callback handover. A full 250-case bulk operation with lazy Agent enrollment, notification creation and callback transfer is covered.

1. Submitted-search behavior during auto-refresh, out-of-order responses and Settings/Dashboard Back/Forward navigation.
2. Complaint create, Fetch, L2 claim/return/correction/resubmit, L3 resolution and CSV export.
3. Reference directory search, both phone fetch buttons, draft preservation and manual creation.
4. Ready Pending cases and the remaining 250 reference customers.
5. Workspace selection, creation, remembered selection, browser navigation and draft isolation.
6. Admin distribution preview/apply, live Agent notifications/list refresh, resolution, personal progress and staff drilldown.
7. Layout widths 1920/1440/1024/390, mobile menu/Escape and desktop collapse.
8. Local portal login/logout, student CRM entry, staff settings and portal-page compatibility.

TypeScript and lint checks pass for the changed application code. The production build and post-deployment health/data checks are part of release verification, rather than substitutes for local workflow tests.

## Production baseline

Read-only inspection found 500 complaints and 500 history records across Batch 01 and Batch_02. Training customers total 500 per workspace; Batch 01 additionally retains ten older dummy records. No existing returned cases or open Agent callbacks with a mismatched owner were present, so no live complaint repair or reassignment is needed. This release needs no database migration. Back up the CRM database before deploying, preserve all existing identities/history, and retain SSH access until the user asks to revoke it. No unrelated project files, databases or containers are changed or deleted.
